## Vision

### 10x Check

The 10x version of this repo is a curated library of hardened, security-first reusable workflows
that any team can drop into their CI/CD pipeline. A "stdlib" for GitHub Actions: Teams notifications,
.NET build/test pipelines, release automation, security scanning, Dependabot management, health checks,
PR automation, and deployment gates. Each workflow follows the same security patterns (harden-runner,
pinned SHAs, minimal permissions, egress blocking). A new repo gets full CI/CD in <5 minutes by
calling shared workflows.

## Architecture

### Naming Convention

- **Reusable workflows** (called by other repos): Clean names (e.g., `release.yml`, `dotnet-build-test.yml`)
- **Internal workflows** (this repo's own CI): Prefixed with `_` (e.g., `_ci.yml`, `_release.yml`)

### Consumption Pattern

Consuming repos use thin wrappers (~10 lines) that define the trigger and call the reusable workflow:

```yaml
# Example thin wrapper in consuming repo
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build:
    uses: marcus-hooper/workflows/.github/workflows/dotnet-build-test.yml@v2
    with:
      dotnet-version: '10.0.x'
    secrets:
      codecov-token: ${{ secrets.CODECOV_TOKEN }}
```

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Consumption pattern | Thin wrappers | Standard GitHub pattern. ~10 lines per wrapper, ~100+ lines centralized. |
| .NET version strategy | Single version input | Simple. Repos needing multi-version call workflow twice. |
| Vulnerable package handling | Fail by default, input to warn | Security-first. `fail-on-vulnerable: true` default. |
| Naming convention | Clean names for reusable, `_` prefix for internal | Reusable workflows are the product. Clean API paths. |
| Versioning | v2.0.0 (major bump) | Signals product evolution. Consumers opt in via `@v2`. |

## Reusable Workflow Specifications

### changelog-check.yml
- **Inputs:** `changelog-path` (default: CHANGELOG.md)
- **Purpose:** Validates Keep-a-Changelog format with `## [Unreleased]` section
- **Source repos:** 6/8

### pr-size-label.yml
- **Inputs:** Size thresholds (XS/S/M/L/XL line counts)
- **Purpose:** Labels PRs by size for review prioritization
- **Source repos:** New pattern

### dotnet-build-test.yml
- **Inputs:** `dotnet-version`, `test-filter`, `run-format-check`, `fail-on-vulnerable`, `codecov-token`
- **Purpose:** .NET format check, NuGet restore with caching, vulnerability scan, build, test, coverage
- **Source repos:** dataverse, restverse, TimeHub, Typeverse, WaterLog

### release.yml (reusable)
- **Inputs:** `changelog-path`, `version-source` (tag/project-file), `generate-sbom`
- **Purpose:** Semver validation, CHANGELOG extraction, major version tag update with retry, SBOM
- **Source repos:** dataverse, send-teams-notification, setup-crmsdk, Typeverse, WaterLog

### security-scanning.yml
- **Inputs:** `language`, `allow-list-path`, `upload-sarif`
- **Purpose:** Gitleaks, dependency review, custom pattern detection
- **Source repos:** send-teams-notification, setup-crmsdk, TimeHub, Typeverse, WaterLog

### dependabot-auto-merge.yml (reusable)
- **Inputs:** `merge-method` (default: squash), `auto-merge-ecosystems`
- **Purpose:** Semver-aware auto-merge, idempotent comments, major update labeling
- **Source repos:** 6/8

### health-check.yml
- **Inputs:** `validation-script` or `validation-commands`, `issue-label`, `cron-schedule`
- **Purpose:** Run validation, create/close GitHub issues on failure/recovery
- **Source repos:** send-teams-notification, setup-crmsdk, TimeHub, Typeverse, WaterLog
